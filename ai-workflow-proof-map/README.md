# How I Keep AI Work Moving

I use AI as a working partner: to make a messy question clearer, keep the important details from getting lost, check the work before it travels too far, and leave the next person with something useful.

## The way I work

1. **Listen for the real question** — I start with what is confusing, repeating or slowing someone down. For example, creators kept asking how to know who they were really selling to.
2. **Make it easier to move through** — I turned that question into a simple buyer-discovery framework people could work through instead of staring at a blank page.
3. **Keep the useful bits close** — I use a knowledge archive so earlier decisions, source material and unfinished work do not vanish halfway through a project.
4. **Check before I carry it forward** — A believable answer is not always the right one. Fresh-read and verify-first checks help me catch that before it becomes a bigger problem.
5. **Use mistakes properly** — When something goes wrong, I write down what happened, why it happened and what would stop it next time. That is what my Mistake Ledger is for.
6. **Leave a clear next step** — The end result should be something useful: a page, a workflow, a document, a dashboard or a decision someone can actually act on.

## Things I have made along the way

- A buyer-discovery framework for recurring creator questions about customer definition.
- Fresh-read and verify-first checks for long-running, source-sensitive work.
- A project memory and knowledge archive.
- A Mistake Ledger for learning from repeated errors.
- AI-assisted websites, an early-product WordPress landing page and a gym-progress tracker used by a friend.
- Daily hands-on work with Claude Code and Codex, alongside Python, Git, GitHub, REST APIs, command-line tools and MCP-style connections.

## What I am getting better at

- Turning a fuzzy request into a workable plan.
- Keeping the right context around a project.
- Telling the difference between an answer that sounds right and one that has been checked.
- Knowing where automation is helpful and where a human decision still matters.
- Explaining a workflow in plain language to customers, collaborators and non-technical people.
