Jebril Osawaru · how I work with AI

I use AI to help real work move forward.

A messy question does not become useful just because a tool gives an answer. I use AI to make the work clearer, keep the right details close, check what matters and leave people with a practical next step.

From “I don’t know where to start”
to “here is the next clear step.”That is the kind of work I enjoy building with AI.

What that looks like in practice

I work hands-on with Claude Code and Codex, plus practical Python, Git, GitHub, REST APIs, command-line tools and MCP-style connections. The point is never the tool by itself. It is whether the person using the result can move forward with confidence.

Hands-on practice

How I work through it

I do not start by throwing a prompt at the problem. I work through it in a way that keeps the answer useful for the person at the other end.

01

Listen first

Find the question, friction or repeat problem before choosing a tool.

02

Make a path

Turn the problem into simple steps and a next action that makes sense.

03

Keep the thread

Hold on to the source, decisions and open work instead of losing them halfway through.

04

Check the work

Read fresh and verify before treating a plausible answer as the answer.

05

Learn from it

Use mistakes to make the next version stronger instead of repeating the same slip.

06

Leave it useful

Finish with a page, workflow, document, dashboard or decision someone can use.

Where this has shown up in my work

Helping creators get clearer

Creators kept asking who they were really selling to. I created a buyer-discovery framework that gave them a way to work through the question instead of guessing.

Keeping a long project steady

I built fresh-read checks, a project memory and a Mistake Ledger so earlier decisions and lessons do not disappear when the work gets long.

Turning ideas into something usable

I have used this working style in AI-assisted websites, an early-product WordPress page, Codex automations and a gym-progress tracker a friend uses.

What I am still learning

I am getting better at turning vague requests into a useful plan, keeping the right context around a project, checking work before it travels too far, knowing where automation helps and explaining a workflow in plain language.
